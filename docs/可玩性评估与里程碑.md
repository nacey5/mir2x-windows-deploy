# mir2x 可玩性评估与里程碑

日期：2026-11-06（北京时间）。目标已确认：朋友小范围试玩，新人能独立玩满 30–60 分钟。

## 判断

值得沿用当前项目继续做。底层战斗、地图、NPC、物品、任务和联网已有大量实现，先把现有系统串成能理解、能完成、能重复的一小时流程，比立刻重做引擎或堆大量活动更合适。

当前最准确的状态是“已部署的开发底座，首小时体验尚未验收”。缺新手入口和活动界面确实影响体验，但更先要解决的是正常新角色能否完成战斗、补给与成长循环。原 README 将两条未移植传奇刀主线概括成“没有剧情主线”，掩盖了已有职业和支线内容，本轮已纠正。

这是一轮针对核心路径的代码与安装包审查，不是所有源码逐行审计，也不是已完成全职业试玩、压测或经济平衡测试。暂不使用没有依据的“完成度百分比”。

## 业内做法：借鉴目标管理，不照搬付费活动

这是两个具体官方产品例子，不是全行业统计：

- FFXIV 的 Main Scenario Guide / Duty List 将下一目标保留在界面上，Active Help 可回看。可借鉴“随时知道下一步做什么”和“说明可重新打开”。[官方界面手册](https://na.finalfantasyxiv.com/game_manual/view/)
- WEMADE 的 LEGEND OF YMIR 活动入口有等级条件、活动有效期、任务条件与领奖说明。可借鉴规则透明、锁定原因和奖励状态，不需要在朋友试玩版照搬通行证或付费机制。[官方 Event / YMIR Pass 指南](https://www.legendofymir.com/en/contents/guide/656631)

对本项目的设计推论：先有明确目标、能执行的行为和可感知回报，再考虑活动窗口的样式。每个活动至少需要入口、条件、目标、进度、奖励、结束/重置规则、异常恢复；光画一个活动面板不会自动产生这些能力。

## 首小时目标体验（设计目标，尚未达到）

| 时段 | 玩家应能做到 | 验收观察 |
|---|---|---|
| 前 5 分钟 | 知道如何移动、查看装备、找引路人 | 不依靠服主口述或后台改库 |
| 5–15 分钟 | 正常获得可用武器/补给，完成首次击杀与拾取 | 血量、掉落、经验反馈一致 |
| 15–30 分钟 | 完成一段职业任务，学习或使用技能，补给后再出发 | 接取、目标、完成、奖励完整；没有必然亏空 |
| 30–60 分钟 | 达到合理阶段后参与可达的重复活动，或与朋友合作 | 有可选目标；退出重登不丢进度；失败后能继续 |

这不是强制把新人塞进 20 轮跑腿。后续优先将低等级每日任务限制在安全可达区域，并把目标、地图、坐标写入任务追踪；再添加一个使用真实击杀进度的小目标活动。限时 BOSS、排行榜和大量签到奖励排后。

## 时间估算

以下是基于本轮源码检查的工程估算，不是行业平均值，也不是交付承诺。假设一名熟悉 C++ / Lua 的开发持续投入、资源可用、使用当前 Windows 版本、主要复用既有任务。等待用户试玩、工具受阻、构建依赖下载不计入有效开发时间；目前核心战斗未验收，估算置信度中低。

| 累计里程碑 | 预计工作量 / 排期 | 通过标准 |
|---|---|---|
| M0 可测底座 | 1–3 个有效工作日 | 隔离测试库、稳定输入、登录与完整战斗补给循环有证据；确认版本和构建路径 |
| M1 首小时试玩 | 5–10 个有效工作日，约 1–2 周 | 引导可发现、三职业至少一条完整路线、基础技能、死亡恢复、重登和两人试玩通过 |
| M2 可重复的朋友服 | 累计约 3–6 周 | 本地化每日目标、正式进度/领奖状态、成长与补给节奏调整、多次重启/多人回归 |
| M3 公开运营 | 当前不承诺日期 | 先完成权限/经济安全、构建发布、备份恢复、并发压测和运营支持评估，再估算 |

若 M0 暴露输入、伤害判定、存档或构建链路的底层问题，应重新估算，不能继续照原日历承诺。“一两天把活动界面画出来”与“新人愿意玩一小时”是不同验收目标。

## 实施顺序与验收关口

1. **P0：完整玩法与可测性。** 新建三职业测试角色，不使用旧高等级号替代；击杀、掉落、经验、装备、用药、学技能、死亡复活、重登；两名玩家一起打一轮。记录失败点和用时。
2. **P1：新手第一条路。** 确定正常建号装备/金币/技能来源，避免出生配置与职业任务起点错位。增加当前目标和恢复提示，检查 800×600 对话显示。不要用一次性强装备掩盖数值问题。
3. **P1：活动入口到可完成。** 本轮先复用每日跑腿；下一步补安全地图目标池、任务追踪、进度/剩余次数、明确重置时区。奖励需覆盖重复点击、断线、背包满、重启和跨日，经济平衡通过后再增加种类。
4. **P2：朋友一起玩的理由。** 一项合作精英目标、合理掉落和成长选择。先记录完成用时、药品消耗、死亡次数，再调经验与掉率；没有数据时不承诺平衡。
5. **独立技术前置：可重复构建与权限。** 建立源码工作分支和构建产物版本关联，核查调试消息权限。不得把客户端隐藏命令当成服务端权限控制。

试玩验收样本建议为至少 3 名没有看过源码的朋友（这是项目验收建议，不是行业基准）。记录首次击杀用时、首次任务完成用时、卡住次数、死亡恢复、退出/重登以及是否愿意继续。任何人必须靠服主手工改库才能继续，都记为失败或已知阻塞，不美化成“已可玩”。
